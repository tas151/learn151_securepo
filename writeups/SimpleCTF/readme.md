# 脆弱性検証レポート（簡易版）: TryHackMe - Simple CTF 編

本リポジトリは、ターゲットサーバーに対する脆弱性診断の実践疑似記録。
ただツールを実行するだけでなく、**「インフラエンジニアの視点」**から、脆弱性の根本原因の分析、および現実的な運用の制約を踏まえた対策の考察までを行った。

---

## 1. 診断概要 & 対象環境
* **ターゲット環境:** Linux OS (Ubuntu)
* **主な検知ミドルウェア:**
  * FTP (21/tcp) -> vsftpd 3.0.3
  * HTTP (80/tcp) -> Apache 2.4.18 (CMS Made Simple 2.2.8 稼働)
  * SSH (2222/tcp)

---

## 2. 発見された脆弱性とリスク評価（アタックサーフェス）

今回の検証において、以下の**5つのセキュリティ不備・脆弱性**をチェーン（組み合わせる）させることで、最終的にサーバーの最高権限（root）を奪取できることを確認した。

### ① 暗号化されていないFTPポートの開放 & 設定不備
* **内容:** 21番ポートが開放されており、さらにデフォルト設定の不備により **Anonymous（匿名）ログイン** が有効化されていた。
* **リスク:** 通信が平文のため盗聴リスクがあるほか、誰でもサーバー内の一部のファイルを閲覧・奪取できる状態になっていた。

### ② 不用意なテキストファイルの残存（情報の暴露）
* **内容:** FTP領域に、認証情報のヒント（パスワードの推測に繋がる文字列）が記載されたテキストファイルが放置されていた。

### ③ CMS Made Simple のSQLインジェクション（CVE-2019-9053, CVSS8.1 high)
* **内容:** Webサーバー上で動く「CMS Made Simple (v2.2.8)」に、既知の重大なSQLインジェクションの脆弱性が存在していた。
* **リスク:** 上記②で得たヒントと組み合わせることで、データベース内から本来見えないはずの管理者ユーザーのソルト付きパスワードハッシュを外部から標的型攻撃（クラック）により割り出すことが可能であった。

### ④ 運用利便性を優先した不適切な権限付与（SUIDの悪用）
* **内容:** サーバー内部のテキストエディタ（vim）に対し、運用・構築時の利便性を優先した結果、所有者権限（SUID）が不適切に付与されていた（**「最小権限の原則」の逸脱**）。
* **リスク:** 一般ユーザーでログインに成功した後、このvimの権限を悪用（特権昇格）することで、容易にroot権限を奪取されるシステム構造になっていた。

---

## 3. 技術的アプローチとトラブルシューティング
既知の脆弱性（CVE-2019-9053）を実証する際、一般に公開されているPoCスクリプトが Python 2 基準であったため、環境依存のエラー（Python 3における文字列 `str` とバイト列 `bytes` のエンコードの差異）に直面した。

* **アプローチ:** 安易に諦めるのではなく、`lib2to3` によるコードの自動変換や、vimでのタブ変換、ミドルウェア（Web-DB間）の通信フェーズにおけるエンコード処理のデバッグ（encode('UTF-8')追加など）を試行した。
 
* **実務を見据えたタイムマネジメント判断:**
  ４日間もの間移植しようしたからこそ、「コードの移植にこだわらず全体の工数を意識しなければならない。ある程度の時間でできなければ別の方法で試すことが重要」だという教訓を得た。

* **最終判断:**
  「限られた時間（案件工数）の中で、確実に脆弱性を実証・報告してリスクを取り除く」という診断実務の本質に立ち返り、4日目の段階でコード修正を断念。迅速に検証環境を Python 2 へ切り替える現実的なルートを選択し、即座に目的であるパスワードハッシュの奪取、および次ステップへの侵入に成功。

## 4. インフラ視点に基づく現実的な対策提案

脆弱性診断士として、単に「パッチを当ててバージョンアップしてください」という一辺倒な報告ではなく、実際の運用現場の制約を考慮した**段階的な対策**を提案する。

| 脆弱性 | 恒久的な対策 | 現実的な次善策 |
| :--- | :--- | :--- |
| **FTPの危険性** | FTP（21番）のサービス完全廃止。暗号化された **SFTP（22番）** へのリプレイス。 | 21番ポートの接続元IP制限、および `Anonymous` ログインの即時無効化。 |
| **CVE-2019-9053** | CMS Made Simple を脆弱性が修正された最新バージョンへアップデート。 | 互換性問題等で即時アップデートが困難な場合、攻撃対象である `moduleinterface.php` への外部アクセスを遮断（WAFやApache設定による制御）。また、原因である「Newsモジュール」が未使用であれば、該当モジュールを無効化する。 |
| **特権昇格（vim）** | vimコマンドのSUID設定（`chmod u-s`）を解除し、**「最小権限の原則」**を徹底する。 | 運用上どうしても一般ユーザーに特権が必要な場合は、`sudoers` ファイルで実行可能コマンドを厳格にホワイトリスト化する。 |

### 🛠️ 総括
現在のインフラ運用保守の現場でも痛感していますが、構築・運用時の「利便性」と「セキュリティ」は常にトレードオフの関係にある。本番環境においてはデフォルト設定を排除し、不要なサービス（ポート）を徹底的に削ぎ落とす**ハードニング（要塞化）**の意識が不可欠であることを、本CTFの検証を通じて深く学んだ。
